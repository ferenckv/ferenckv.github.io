# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a Jekyll-based personal website/portfolio (ferenckv.github.io) built on the [devlopr](https://github.com/sujaykundu777/devlopr-jekyll) theme. It is a static site: content lives in Markdown/YAML front matter, and Jekyll renders it through Liquid layouts/includes into static HTML for deployment to GitHub Pages.

## Environment setup (read this first)

The most common way to get stuck here is running under the wrong Ruby. macOS ships a system Ruby at `/usr/bin/ruby` (2.6); this project does **not** use it.

- Ruby is pinned to **3.4.10** via `.ruby-version`, managed with **rbenv**.
- Bundler is pinned by `Gemfile.lock`'s `BUNDLED WITH` line (**4.0.20**). Bundler 4.x requires Ruby ≥ 3.4.1, so it cannot run under system Ruby at all.

Before anything else, confirm rbenv is actually intercepting `ruby`/`bundle` in this shell — having rbenv *installed* is not the same as its shims being on `PATH`:

```bash
which ruby bundle && ruby -v
```

Expected: paths under `~/.rbenv/shims/...` and `ruby 3.4.10`. If instead you see `/usr/bin/...` and `2.6`, rbenv's init hasn't loaded. Fix it for the current shell, then make it permanent:

```bash
eval "$(rbenv init - zsh)"      # bash: use 'bash'; put this line in ~/.zshrc (zsh) or ~/.bash_profile (bash)
rbenv install -s 3.4.10          # -s = skip if already installed
gem install bundler:4.0.20       # must match Gemfile.lock's BUNDLED WITH, or `bundle` won't activate
bundle install
```

The check that matters is `which ruby` returning a **shim path**, not merely "rbenv is installed."

## Commands

```bash
# Serve locally with live reload (default: http://localhost:4000)
bundle exec jekyll serve

# Build the static site (outputs to ./build, per `destination` in _config.yml)
bundle exec jekyll build
# equivalent rake task:
rake assets:precompile

# Build AND validate the generated HTML (see "Verifying changes")
bundle exec rake htmlproof
```

Production runs via Puma (`Procfile`) and `config.ru` (`Rack::Jekyll`), but the deployment target is GitHub Pages (`DEPLOY_STRATEGY` is set to `gh-pages`), so that path is legacy and not exercised by deploys.

## Verifying changes (definition of done)

There is no unit-test suite. Because this is a static site, an agent cannot see the rendered page — verification is done by building and validating the generated HTML. After **any** content or template change, run:

```bash
bundle exec rake htmlproof
```

This task (defined in the `Rakefile`) builds the site to `./build`, then runs `html-proofer` over the output. It catches two classes of failure:
- `jekyll build` failing — Liquid syntax errors and malformed front matter.
- HTML that builds *clean* but renders broken — dead internal links, missing image files, missing `alt` attributes, malformed markup.

A change is not "done" until `rake htmlproof` exits 0. (`html-proofer` is in the Gemfile's `:test, :development` group; run `bundle install` if it's missing. The same task runs in CI via `.github/workflows/build.yml`.)

The task sets `disable_external: true` so CI never fails on a third-party timeout (LinkedIn, GitHub, `company_url`s). To audit outbound links occasionally, run `bundle exec htmlproofer ./build` by hand with external checking on.

## Do not edit

- `build/` — generated output. Regenerated by every build; never hand-edit.
- `assets/bower_components/` — vendored front-end libraries (Bootstrap, Font Awesome, isotope, lightgallery). Never hand-edit; excluded from Jekyll processing in `_config.yml`.
- `.forestry/settings.yml` — legacy Forestry CMS config, unused.
- `admin/` — leftover Netlify CMS UI from the now-removed `jekyll-admin` gem (see Known quirks). Vestigial; do not wire it back in without a Rack-3-compatible replacement.
- `.ruby-version` / `Gemfile.lock` `BUNDLED WITH` — deliberate version pins. Do **not** downgrade them to satisfy an older Ruby; fix the environment instead (see above). If you upgrade Ruby/bundler, update both together and commit the lockfile.

## Known quirks

- **Bundled-gem shims — do not remove.** `csv`, `base64`, `logger`, and `bigdecimal` are declared in the Gemfile purely because Ruby 3.4 demoted them from default gems to *bundled* gems; Jekyll's dependency chain still `require`s them. They look like unused dependencies but removing any of them breaks the build with a `LoadError`.
- **jekyll-admin was removed** — version 0.11.1 (its last release) references the Rack 2 `Rack::Handler` API, which Rack 3 deleted (pulled in via sinatra 4). It crashed `jekyll serve` and has no fixed release. The site is edited via files/CI, not the `/admin` GUI. Do not re-add it without pinning `rack '~> 2.2'`.
- **html-proofer URL swap.** `rake htmlproof` maps the `https://ferenckv.github.io` origin to local paths via `swap_urls`. This is required because templates bake absolute `{{ site.url }}` links (nav, favicon, author avatar); without the swap, html-proofer classifies them as external and skips them, leaving your own nav unchecked.
- `_config.yml` declares a `products` collection (`output: true`) but there is no `_products/` directory — it is unused. Don't assume a products section exists.
- Some `_authors/` and `_data/` files use CRLF line endings; preserve them to avoid noisy diffs.

## Architecture

**Content vs. presentation split (standard Jekyll):**
- `_config.yml` — central site configuration: author bio, work experience, education, and project lists (rendered on the homepage/about page), navigation (`urls`), pagination, collections, plugins, and the `destination: ./build` output path. Most personal/profile content edits happen here rather than in templates.
- `_layouts/` — page skeletons selected via each page's `layout:` front matter. `default.html` is the outermost shell; other layouts (`home`, `post`, `page`, `about-me`, `contact`, `gallery`, `author`, `full-width`) wrap `default` or `compress`. `compress.html` is a whitespace-minifying wrapper used by `default`. The about/homepage profile UI lives in `_layouts/about-me.html`.
- `_includes/` — reusable Liquid partials (e.g. `header.html`, `footer.html`, `hero.html`, `author.html`, `blog_post_article.html`, contact-form and comments partials). Many features are opt-in and gated on whether the corresponding `_config.yml` value is set.
- `_data/` — YAML consumed by templates: `authors.yml` (multi-author) and `galleries/*.yml`.
- `_posts/` — blog posts (date-prefixed Markdown, `layout: post`).
- `_authors/` — one Markdown file per author, paired with a `_data/authors.yml` entry, rendered via the `author` layout.
- `assets/` — `css/main.scss` (Sass entry, pulls in `_sass/devlopr.scss`), `js/`, and `img/`. Content images resolve as follows: profile/company/college logos at `assets/img/<filename>`, author avatars at `assets/img/authors/<filename>`, post images at `assets/img/posts/<post-slug>/`, gallery images at `assets/img/gallery/<directory>/`.

**Key coupling:** because most homepage/about content (work experience, education, projects, social links) is data-driven from `_config.yml` rather than hardcoded in layouts, adding or editing that content is a **config change, not a template change**. Template edits are only needed to change *how* that data is displayed.

## Common tasks

Field names below are exact and load-bearing — the templates read them by key. Match the existing entries in each file. After any of these, run `bundle exec rake htmlproof`.

### Add / edit work experience, education, or a project
All three are lists in `_config.yml`, gated by the `show_author_*` toggles (`show_author_work_experiences`, `show_author_education_details`, `show_author_project_details`).

Work experience — under `author_work_experiences:`:
```yaml
- company_name: Example Co
  company_logo: example.png        # place the file in assets/img/
  company_url: https://example.com
  designation: Senior Engineer
  description: One-line summary
  ternure: Jan 2025 - Present      # SIC: spelled "ternure". The template reads exp.ternure —
                                   # renaming it to "tenure" silently drops the date line.
  visibility: true
```

Education — under `author_education_details:`:
```yaml
- college_logo: example.png        # assets/img/
  college_name: Example University
  college_url: https://example.edu
  college_degree: CS Engineer
  description: Bachelor of Technology
  visibility: true
```

Project — under `author_project_details:`:
```yaml
- project_title: Example API
  project_description: What it does.
  tech_stack:
    - Kotlin
    - Spring Boot
  visibility: true
```
Set `visibility: false` to hide an entry without deleting it.

### Add a blog post
Create `_posts/YYYY-MM-DD-slug.md`. Put images in `assets/img/posts/<slug>/`.
```yaml
---
title: Post title
layout: post
author: ferenckv                                   # must match an author key (see below)
date: 'YYYY-MM-DD HH:MM:SS -0600'
thumbnail: "/assets/img/posts/<slug>/cover.png"
category: jekyll                                    # single category
summary: One-line description used in listings.
keywords: space separated keywords
permalink: "/blog/YYYY-MM-DD-slug/"
---
```

### Add or edit an author (two files, kept in sync)
An author is **two coupled files**. Editing one and not the other leaves the site half-updated but still building — this repo already shows the drift: `_authors/ferenckv.md` says "Senior Software Engineer" while `_data/authors.yml` says "Web Developer." Always change both.

1. `_authors/<username>.md` front matter: `name`, `username`, `bio`, `site`, `avatar`, `email`, `social` (list of `{title, url}`).
2. `_data/authors.yml` — a top-level key `<username>:` with the same fields.

Avatar image goes in `assets/img/authors/<avatar>`. The `<username>` is the value used as `author:` in post front matter.

### Add a gallery album
Albums are entries in a `_data/galleries/<name>.yml` list; images live in `assets/img/gallery/<directory>/`.
```yaml
- title: Album Title
  directory: album-dir             # folder under assets/img/gallery/
  preview:
    filename: 1.jpg
    original: 1-thumbnail.jpg
    sizes:
      - 1-thumbnail.jpg
    thumbnail: 1-thumbnail.jpg
```
